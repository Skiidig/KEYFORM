## 2. Keycap Grouping, Escape Accent Precedence & Legend Contrast Shader

### Semantic Keycap Grouping Policy (`src/runtime/three/buildConfigRuntime.ts`)
Derived exclusively from `manifest.keys` metadata (never GLB child order):
- **Uniform set (`charcoal-pbt`):** All 81 keys restore canonical linear Charcoal PBT `[0.01009, 0.013804, 0.012702]` (`#1A1F1E`).
- **Two-tone sets (`porcelain-pbt`, `two-tone-slate`):**
  - **Alpha / typing-field group (48 keys):** `spec.semantic_finish_role === 'alpha'` (47 keys) plus convex Spacebar (`spec.is_convex_space === true`, 1 key).
    - `porcelain-pbt`: `#ECE9DF` (warm porcelain).
    - `two-tone-slate`: `#D9DDD8` (light slate).
  - **Outer modifier group (33 keys):** `spec.semantic_finish_role === 'modifier'` (excluding `Space`, 32 keys) plus `Esc` (`spec.semantic_finish_role === 'accent_optional'`, 1 key when `accent === 'matched'`).
    - `porcelain-pbt`: `#D8D4C7` (muted warm grey).
    - `two-tone-slate`: `#434A46` (deep graphite).

### Escape Accent Precedence
Resolved deterministically in `resolveKeycapAppearanceMap`:
1. **Base keycap set** (`config.keycaps`)
2. **Explicit Escape accent** (`config.accent !== 'matched'` overrides only canonical `Esc`)
3. **Future per-key overrides** (`config.keyOverrides?.[keyId]` / `ProductionScene.setKeyColorOverrideWithLegend` — highest precedence, ready for KF-006B)

Changing `config.keycaps` preserves any explicit non-matched `config.accent`; selecting `matched` restores `Esc` to the active base keycap set color and matching legend contrast.

### Per-Instance / Per-Mesh Legend Contrast Shader Contract (`src/runtime/three/legendMask.ts`)
Because `InstancedMesh` batches merge alpha and modifier 1u keys (e.g., `Two-Tone Slate` light alphas + dark modifiers inside a single `MAT_Keycap_PBT` batch), a single shared legend color uniform cannot represent mixed light/dark keycaps simultaneously.
- Added `attribute vec3 kfLegendTint` (`THREE.InstancedBufferAttribute` with `DynamicDrawUsage` on instanced batches; `THREE.BufferAttribute` on the 6 single-instance keycap meshes), passed via `varying vec3 vKfLegendTint` and blended in `#include <color_fragment>` (`diffuseColor.rgb = mix(diffuseColor.rgb, vKfLegendTint, kfMask)`).
- **Zero extra draw calls, zero extra textures, zero extra shader programs.**
- **Contrast policy (`resolveLegendTintForHex`):** Computes WCAG linear relative luminance `L = 0.2126*r + 0.7152*g + 0.0722*b`. Caps with `L >= 0.18` (Porcelain alphas/mods, Two-Tone Slate alphas, Ivory Esc, Brass Accent Esc) receive calibrated matte dark charcoal legends (`DARK_LEGEND_LINEAR` = `#202524`, linear `[0.014444, 0.018500, 0.017642]`); caps with `L < 0.18` (Charcoal PBT, Two-Tone Slate modifiers, Forest Esc) receive canonical `MAT_Legend_Light` (`#CBD1C8`, linear `[0.594804, 0.635081, 0.575242]`).
- **Preserved invariants:** Persistent `kfLegendUniformRefs` (with per-material owner UUID tracking so cloned single-instance materials never double-wrap `onBeforeCompile` or serialize `DataTexture` in `userData`), pre-legend visibility gate, blank `Space`, and automatic re-application of cap colors and `kfLegendTint` across `2048 <-> 1024` quality-tier transitions.

## 3. Configuration Pipeline, Lazy Boundaries & Static Fallback

- **Lazy Build Studio runtime chunk (`src/runtime/three/buildConfigRuntime.ts`, `1,630 B` gzip-9):** Dynamically imported inside `viewportAdapter.ts` exclusively when `station === 'build-studio'` activates. Initial visitor load retains `1` `<script>` tag and `0` WebGL/audio requests; Mechanical Anatomy and Switch Lab never fetch Build Studio's material tables.
- **Deterministic dirty-tracked application (`createBuildConfigApplier`):** Tracks applied state per partition (`exterior` vs `internal`). Changing `switchProfile` or `plate` in exterior-only view records state without fetching `kf01_internal_b21.meshopt.glb` and triggers zero unnecessary renders. When `Exploded` or `Rear` triggers `loadInternal()`, the latest `BuildConfig` is applied immediately before rendering, stale async completions are ignored via `revision` guards, camera/user orbit is preserved on material edits, and steady idle renders zero frames.
- **Static fallback & context loss:** React (`src/App.tsx`) remains the single source of truth for `BuildConfig`. Static disclosures accurately separate the four photographed enclosure renders from live 3D materials (`matched`, `partial`, `reference`), pairing strip swatches stay synchronized (including `Matched` Escape reflecting the selected keycap set), and context loss or viewport handoff never resets the build.

## 5. Known Limitations & KF-006B / KF-006C Handoff

### Limitations
- Installed switches (`GRP_03_Switches`) are material-only previews on shared opaque MX geometry (`transmission = 0`, `4.0 mm` installed travel).
- Polycarbonate switch plate (`GRP_04_SwitchPlate`) uses an opaque frosted dielectric PBR approximation (`transmission = 0`) rather than physical refraction.
- Node 22.x parity, clean uncontested RTX 4060 GPU frame timings, and physical mobile/iGPU validation remain open KF-007 release gates.

### KF-006B & KF-006C Extension Points
1. **Per-Key Customization (`KF-006B`):**
   - `BuildConfigState.keyOverrides?: KeycapColorOverrides` is already typed in `src/runtime/types.ts` and honored with highest precedence in `resolveKeycapAppearanceMap` (`src/runtime/three/buildConfigRuntime.ts`), automatically computing per-key `kfLegendTint` luminance contrast for arbitrary HEX values across both instanced and single-instance keycaps.
   - `ProductionScene.pickFromRay` already resolves all 81/81 canonical key IDs and the encoder without relying on node order.
   - Keep individual key picker / multi-selection / custom HEX controls in a lazy Build Studio UI module (`index-*.js` currently has `60 B` headroom under `90,000 B`).
2. **Interaction Modes (`KF-006B` / `KF-006C`):**
   - `BuildStudioInteractionMode = 'configure' | 'customize' | 'typing' | 'inspect'` and optional `BuildStudioViewportState.interactionMode` are typed in `src/runtime/types.ts`, cleanly orthogonal to the `Exterior` / `Keycaps` / `Internals` configuration tabs.
3. **Typing Mode & Audio (`KF-006C`):**
   - Reuse `ProductionScene.keyIdForDomCode`, `pressKey`, `releaseKey`, and lazy `src/audio/MechanicalAudioEngine` (`keyDown` / `keyUp` / `setProfile`) behind explicit sound activation.
