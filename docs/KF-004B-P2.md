## 2. Scoped Runtime & Adapter Adjustments

The single-owner renderer lease (`rendererLease.ts`), lazy loading, asset integrity verification (`assets.ts`), demand frame loop, AgX tone mapping, procedural PMREM studios, contact shadows, and `ProductionScene.ts` were preserved untouched. Three narrowly scoped adapter/stage additions resolved demonstrated visual and interaction defects:

1. **`ViewportRuntimeAdapter.resetView?()` (`src/runtime/types.ts`, `viewportAdapter.ts`, `NativeStage.ts`):** Clears `userOrbited` and runs `setCamera(this.preset, false)` (interruptible 420 ms ease-out, instant under `prefers-reduced-motion`), settling back to 0 idle frames.
2. **`NativeStage.setBottomInset(insetPx)` (`NativeStage.ts`, `viewportAdapter.ts`):** Bound exclusively for `build-studio` via `matchMedia('(min-width: 640px)')` (`72 px` when HUD floats, `0 px` when docked below; listener cleaned up on `dispose()`). Scales `fitHalfH` against usable open height and applies `camera.setViewOffset` so all four Build Studio presets clear the floating HUD without changing `CAMERA_PRESETS`, `runtime-fixture.ts`, Anatomy, or Switch Lab.
3. **Manual-orbit resize preservation (`NativeStage.ts`):** `ResizeObserver` updates `camera.aspect`, view offset, and renderer size on every resize, but refits the canonical preset only when `!userOrbited` so resizing never destroys an intentional user camera angle.

Focused regression coverage was added in `tests/scripts/smoke-runtime.mjs` verifying `Reset view` invalidation + zero-idle settle and Anatomy `Assemble`/`Explode` `aria-pressed` states.
